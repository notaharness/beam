# 02 · Identity, membership, revocation

## One key per machine

A machine's identity is its WireGuard **node key**, a Curve25519 keypair generated by
tailcat on first run and never rotated. The public half is what peers pin and what the
owner's passkey signs for. Nothing a machine sends to a peer carries a signature of its
own: it travels through a tunnel that already authenticates the sender.

```
peerId = lowercase hex of the first 8 bytes of SHA-256(nodePublic)        16 characters
```

`nodePublic` is the raw 32-byte key. The id is derived, not minted, so every machine
computes the same id for the same key. It is a path segment and is validated as exactly
16 lowercase hex characters wherever it arrives from outside.

A `label` is a human name, chosen at join, defaulting to the hostname. 1–64 characters,
no `/`, `\`, `{`, `}` or control characters. Rejected, never rewritten.

## Fleet keys from the passkey

One WebAuthn credential per owner, relying party `pair.n10.is`, created with
`residentKey: required`, `userVerification: required`, and the `prf` extension. The PRF
extension makes the authenticator return `HMAC(credential secret, salt)` for a salt the
caller chooses, 32 bytes, reproducible only by that authenticator, only after user
verification. Two salts, evaluated in one assertion:

| Salt (UTF-8) | Output | Derived | Where it lives |
|---|---|---|---|
| `beam:fleet:v1:seed` | `S` | `MSK, MPK = Ed25519 keypair from seed HKDF(S, "membership")` | `MSK` in memory for the duration of one ceremony, then zeroed. `MPK` in every machine's `fleet.json`. |
| `beam:fleet:v1:dir` | `D` | `K_dir = HKDF(D, "directory")`, `K_auth = HKDF(D, "worker-auth")` | Both cached in every machine's `fleet.json`, `0600`. |

```
fleetId = lowercase hex of SHA-256(MPK)                                    64 characters
```

`MPK` identifies the fleet. `MSK` is the only thing that can add or remove a machine,
and it exists only while the owner's finger is on the sensor, so to speak. `K_dir`
decrypts the directory; `K_auth` proves to the worker that a request comes from a fleet
member. Both are known to every machine and therefore to a stolen one; what a stolen
machine gets from them is addresses and labels, not membership.

PRF requires an authenticator and browser that support it: Chrome and Edge, Safari 18+,
iCloud Keychain, Google Password Manager, Windows Hello, YubiKey 5. The ceremony page
checks `getClientExtensionResults().prf` and fails clearly when it is absent.

## `$BEAM_DIR`

`$BEAM_CONFIG_DIR`, else `$XDG_CONFIG_HOME/beam`, else `~/.config/beam`. Every file is
written as temp file → `0600` → rename over.

```
$BEAM_DIR/
  key.json           tailcat PrivateKey: node key, disco key, PSK, DERP region  0600
  fleet.json         { v, credentialId, fleetId, mpk, kDir, kAuth, entry }     0600
  peers.json         PeerRecord[]                                              0600
  revocations.json   Revocation[]                                              0600
  mailbox/           see 05-mailbox.md
  run/beam.sock      control socket, present while the daemon runs             0600
  run/beam.lock      exclusive lock held by the running daemon
```

`key.json` is tailcat's own `PrivateKey` JSON, written by tailcat's marshaller. `entry`
in `fleet.json` is this machine's own signed membership entry.

## The membership entry

```json
{
  "v": 1,
  "kind": "member",
  "peerId": "…16 hex…",
  "nodePublic": "…base64url 32…",
  "discoPublic": "…base64url 32…",
  "address": "tc…",
  "label": "buildbox",
  "issuedAt": 1758570000000,
  "sig": "…base64url 64…"
}
```

`sig = Ed25519.sign(MSK, "beam-member:v1" ‖ canonical(entry without sig))`, where
`canonical` is JSON with keys sorted, no whitespace, integers unquoted. The disco key is
signed so a peer cannot be steered to a different path-discovery identity than the owner
approved; the address is signed because it contains the PSK peers must use and the
region they should look in.

**Verification**, given `MPK`:

1. `peerId` is 16 lowercase hex and equals the derivation from `nodePublic`.
2. `address` parses, and its embedded node and disco keys equal `nodePublic` and
   `discoPublic`.
3. `label` passes the boundary check.
4. The signature verifies under `MPK`.
5. `peerId` is not in `revocations.json`.

A failure is `bad-entry`, `wrong-fleet` (signature invalid) or `revoked`.

## The revocation

```json
{ "v": 1, "kind": "revoke", "peerId": "…", "issuedAt": 1758570000000, "sig": "…" }
```

`sig = Ed25519.sign(MSK, "beam-revoke:v1" ‖ canonical(record without sig))`. Only a tap
can produce one. Anyone who holds `MPK` can verify one, so revocations are safe to store
in the directory and to forward between peers.

## The directory

An append-only log per fleet, stored by the worker at `pair.n10.is`
([09-build-and-distribution](09-build-and-distribution.md) has the API). Each log entry is

```
nonce(24) ‖ XChaCha20-Poly1305(K_dir, nonce, aad = fleetId, plaintext = member | revoke)
```

The worker sees `fleetId`, a sequence number it assigns, ciphertext and a size. It
cannot read, forge or alter an entry; it can refuse to serve or drop entries, which
readers tolerate because every entry is also held by the machines that have seen it and
is gossiped on `sync` ([04-streams](04-streams.md)). Readers decrypt each entry, verify
it, and ignore anything that fails: a compromised fleet member holding `K_auth` can
append junk, and junk is discarded. Union semantics: there is nothing to roll back.

The directory is **read at join and at daemon start, appended at join and at revoke, and
never polled.** Nothing at runtime depends on it. A machine that never connects to the
worker again keeps working; it learns about newcomers when they connect to it.

## Ceremonies

WebAuthn needs a browser on a real origin, so one static HTML file is hosted at
`https://pair.n10.is/`. It:

1. Reads `location.hash`: `op` (`create` or `get`), `state`, `return`
   (`http://127.0.0.1:<port>/cb`), `label` and `fingerprint` of the machine being acted
   on, and `action` (`init`, `join`, `revoke <label>`) to display.
2. Shows one sentence — "Add **buildbox** (c5aa 18e0 77b2 0d31) to your fleet" — and a
   button.
3. Calls `navigator.credentials.create` or `.get` with `rpId: "pair.n10.is"`,
   `userVerification: "required"`, `extensions: { prf: { eval: { first: salt1, second:
   salt2 } } }`.
4. Navigates to `return#state=…&result=…` with the credential (for `create`) and the two
   PRF outputs, base64url. Everything after `#` never leaves the browser.

`Content-Security-Policy: default-src 'none'; script-src 'sha256-…'`. No network
requests, enforced. No state. Source in `web/pair/`, hash checked in CI.

The daemon side: open a one-shot loopback listener, generate `state`, open the browser
(or print the URL), wait up to five minutes for `/cb`, check `state`, derive keys from
the PRF outputs, do the one signing operation the ceremony was for, zero `MSK`, answer
the browser with "done", close the listener. On a headless machine the user forwards the
port: `ssh -L <port>:127.0.0.1:<port> box`. A phone can approve any machine's ceremony
through WebAuthn's QR hybrid transport, which supports PRF on current iOS and Android.

## Flows

### `beam init` — the first machine, once per fleet

1. Generate `key.json`; pick the best DERP region.
2. Ceremony `create` with PRF. Store `credentialId`. Derive `MPK`, `K_dir`, `K_auth`,
   `fleetId`. Sign this machine's entry with `MSK`; zero `MSK`.
3. Write `fleet.json`. Append the entry to the directory (creating the fleet's log).
4. Start the daemon.

One tap. Some authenticators do not return PRF output on `create`; the page detects
this and performs a `get` immediately after, which is a second tap on those
authenticators only.

### `beam join [--label NAME]` — every other machine, once each

1. Generate `key.json` if absent.
2. Ceremony `get` with PRF, displaying this machine's label and fingerprint. Derive
   keys; sign this machine's entry; zero `MSK`.
3. Fetch the directory. Decrypt and verify every entry; build `peers.json` and
   `revocations.json`. Refuse to continue if this machine's own `peerId` is revoked
   (`wipe $BEAM_DIR to give this machine a new identity`).
4. Write `fleet.json`. Append this machine's entry.
5. Start the daemon. It dials every peer; each admits this machine on first contact
   ([03-transport](03-transport.md)) and dials back.

One tap. No introducer, no address to paste, no confirmation prompt on another machine.
The confirmation is the sentence on the ceremony page.

### `beam revoke <peer>` — from any machine

1. Ceremony `get` with PRF, displaying "Remove **oldlaptop** from your fleet". Derive
   `MSK`; sign a revocation; zero `MSK`.
2. Apply locally: mark revoked, terminate its tunnel and streams. Append to the
   directory. Gossip on the next `sync` with every peer.

One tap. `beam peer forget <peer>` is local amnesia and needs none.

## The peer table

```go
type PeerRecord struct {
    Entry      MemberEntry     // the verified, signed entry; Address and Label inside
    PinnedAt   int64           // unix ms
    LastSeenAt *int64
    Revoked    bool
    RevokedAt  *int64
    LocalLabel *string         // set by `peer rename`; overrides Entry.Label for display
    Scopes     *[]StreamKind   // nil = all; see 04-streams.md
}
```

A record exists only for a verified entry. There is no unverified state.

**Default grant.** `Scopes == nil` means all three kinds. One human, one fleet: every
machine may open a shell on every other on first contact. Narrowing is
`beam peer grant <peer> msg` on the machine being protected.

## Sync and gossip

When a tunnel comes up, each side opens one `sync` stream carrying every member entry
and revocation it holds. The receiver verifies and stores what it lacks. This is how a
machine that was offline during a join or a revoke catches up without consulting the
worker, and how the fleet survives the worker losing its data.

## Losing the passkey

The fleet keeps working; every pin is local. Adding and revoking need `MSK`, which
needs the passkey, so they stop. Recovery is a new fleet: `beam init` on one machine
with a new passkey (new `MPK`, new `fleetId`, new log), then `beam join` on each other
machine. Each keeps its node key and `peerId`; `fleet.json` is rewritten and
`peers.json` rebuilt from the new log. There is deliberately no way to migrate a fleet
to a new root without a tap per machine: any such path would let a peer replace the
owner.

## What is deliberately absent

- A signing key on any machine's disk.
- A join address, an introducer, a pairing prompt on a second machine.
- A device-code flow.
- Runtime traffic to the worker.
- Certificate expiry, key rotation schedules, sign-count tracking.
